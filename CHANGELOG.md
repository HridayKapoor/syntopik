# Changelog

All notable changes to **Syntopik** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- `syntopik interleave --tui`: a mixed drill right in the terminal. Each question comes from a shuffled chapter; you pick the idea it needs (with an "I don't know" option), work it out, see the answer and say whether you got it. Results feed the same review schedule, mistake log and chapter mix-up stats as the dashboard drill. Quitting before answering records nothing.
- `syntopik review --tui`: a card rated "again" comes back once at the end of the same session (a quick second look), like Anki's learning steps. Both answers are recorded.
- `syntopik review --tui` now introduces up to 10 never-reviewed concepts after the due ones (`--new N`, 0 turns it off), like new cards in Anki. Imported flashcard decks were previously impossible to start from the terminal because nothing was "due" yet. `syntopik drop` of a flashcard file now says how many cards were added and points to `review --tui` instead of asking a lesson question.
- `syntopik export anki` now works without the optional genanki package: it writes a tab-separated file that Anki imports directly (File > Import), with cloze cards kept as cloze. Also available as `syntopik export anki-text` and `srs_engine.py export-anki-text`.
- `syntopik profile calibrate` run in a terminal now asks its 4 short questions (Enter skips each). Run without a terminal and with no flags, it still saves defaults but says so.
- Dashboard Exams tab: "Your exams" row on the readiness card to save the picked date as a named exam and remove exams, backed by new `GET/POST /api/exams` (also in the offline demo). Typed values now survive live refreshes of the card. The exam-date logic lives in the new `syntopik/exams.py`, shared with `syntopik pace`.
- `syntopik pace --add-exam NAME --date YYYY-MM-DD`, `--remove-exam NAME` and `--minutes N` set exam dates and daily study time without hand-editing `study-config.json`; readiness and the taper pick the dates up too. With no exams set, `pace` now says how to add one instead of printing a week of empty days.
- `syntopik run` with no engine lists the available engines, and a mistyped engine name gets a "Did you mean" suggestion.
- `python -m syntopik` now works, for setups where the `syntopik` command is not on PATH.
- Empty-vault guidance: `review`, `readiness`, `interleave`, `triage` and `report` now say how to add material (`syntopik drop`, `syntopik demo`) instead of printing bare zeros.
- **Importer plugins (`syntopik/importer_api.py`, `syntopik/kindle_clippings.py`)**: a small, versioned plugin API so new source formats can be added without touching the core. Plugins come from installed packages (entry-point group `syntopik.importers`) or, only after opting in with `"allowLocalImporters": true` in `study-config.json`, from `<workspace>/importers/*.py`. Ships a built-in Kindle `My Clippings.txt` importer. New `syntopik import --list-importers` and `--limit`. Plugins can never inject scheduling state, and every imported item still starts as `planned`.
- **Passphrase-encrypted sync deltas (`syntopik/sync_crypto.py`)**: `syntopik sync-delta export --encrypt` wraps a delta in a `syntopik-delta-enc-v1` envelope (scrypt key derivation, AES-256-GCM, header bound as associated data). Opening is fail-closed on a wrong passphrase, any tampered byte, or unsafe key-derivation settings. The passphrase comes from `SYNTOPIK_SYNC_PASSPHRASE` or a hidden prompt, never the command line. Needs the new optional `sync` extra (`pip install "syntopik[sync]"`); plain deltas are unchanged.
- **Friendlier CLI start**: running `syntopik` with no command prints a short "Start here" guide instead of an error, and a mistyped command suggests the closest match (`Did you mean: review?`).
- **"This Week" card in the Studio Overview**: the weekly progress report (reviews, active days, study time, recall when due, due load, suggested focus) next to last week, served by `/api/state` and a new `GET /api/report?days=N`.
- **"In plain words" README intro** for new, non-technical learners.

### Changed
- `syntopik profile` now starts with "How Syntopik teaches you right now" in plain words: the lesson style, how long explanations are, study habits it asks for, session length, your level per subject, how well your confidence matches your results, and how to change any of it. The short technical summary that AI assistants read is still shown below it, and `--json` is unchanged.
- `syntopik next` now says what to do in plain words, using concept titles, with one line on how to start it (a command, or what to ask your AI assistant). Before, it printed internal move names, ids and details such as "causal_probe" or "cuts 0.50 bits". The `--json` output is unchanged.
- `syntopik readiness` lists its top three next steps in plain words, each with roughly how long it takes and how to start it (a command, or what to ask your AI assistant). Before, it printed internal labels such as "Clear 6 due Blunder Fork(s)" or "Verify bottleneck 'phys-shm-linearization' to T3 transfer". The `--json` output is unchanged.
- `syntopik pace` now names what to study each day: it hands out the exam's not-yet-mastered topics in order (chapter outline first, otherwise weak concepts before unstarted ones), then switches to mixed recall once everything has been covered. Before, every block said "active recall + next core topic". Exams are matched to your material by name too, including short forms such as "ML" for Machine Learning.
- `syntopik triage` now prints a block-by-block plan in plain words (what to fix, re-test or refresh in each block, by concept title) plus a short guilt-free skip list, instead of only three bucket counts. Each plan block also carries a `targets` list in `--json`.
- `syntopik drop` of notes, PDFs, videos or links now says what to do next in plain words: open your AI assistant in that folder and say "Start", or browse it with `syntopik serve --open`. The tutor's warm-up question is labelled as such instead of appearing as the "Next" step.
- `syntopik import` of flashcard files (CSV/TSV, Anki decks, notebooks, note folders) now says how many items were new and how many were already there, so importing the same file twice no longer looks like nothing happened.
- `syntopik rosetta` (cross-subject twin finder) skips keywords whose text cannot appear before running the regex: about 3x faster on a 3,000-concept vault (1.7s to 0.56s), with identical results.
- `syntopik review` with nothing due now says when the next review comes due and how many concepts are not started yet, instead of stopping at "Nothing due right now." A long queue says how many more items are hidden and points to `review --recover`.
- Anki export (`export anki`, `export anki-text`, the review package export) indexes the why-chains once instead of rescanning every link for every concept: a 3,000-concept text export went from about 6s to 0.2s, with byte-identical output.
- Lookalike-concept detection (used by the daily plan and the 5-minute review) now remembers its result on disk in `knowledge-graph/.cache/`, so on a 3,000-concept vault repeat runs take about 0.1s instead of about 9s. Reviews do not invalidate it; editing concepts or links does. Backups skip the cache.
- README and BOOTSTRAP document the new `pace --add-exam/--remove-exam/--minutes` flags. They also tell agents to record exam dates that way, and to pass the calibration answers as flags, because `profile calibrate` only asks its questions in a real terminal.
- Bottleneck ranking (daily plan, 5-minute review, `graph_intel`) is much faster on large graphs without NetworkX. The stdlib betweenness only tracks nodes reachable from each source and skips sources with no outgoing edges. On a 3,000-concept vault that took it from 2.1 s to 5 ms, with bit-identical results.
- Studio `/api/state` is about 6x faster on large notebooks (about 5 s to 0.8 s on a 3,000-concept vault): it now builds only the re-entry brief it uses (`daily_plan.build_reentry_only`) instead of the whole daily plan with its graph scans.
- `syntopik next` shows its suggested command without the machine-only `--json` flag (JSON output is unchanged), and `syntopik review` ends its due list with how to start reviewing.
- Terminal review (`syntopik review --tui`): a mistyped rating now asks again instead of silently skipping the card, each rating shows when the card comes back, and the session ends with a short tally and how many cards are still due.
- The GitHub Pages demo is now rebuilt from current sources at deploy time (with the static checks), on code changes and weekly, so the live demo can no longer drift behind the Studio or show stale dates.
- CI now also runs the core suite on Python 3.13 and 3.14 (Ubuntu), and 3.14 is listed as supported. The full suite was verified locally on 3.14.
- **Faster on large vaults**: on a 20,000-concept workspace, `syntopik next` went from 3.1 s to 1.0 s, `review` from 2.1 s to 0.8 s and `interleave` from 4.9 s to 1.2 s (lazy-greedy due-queue compression, shared ledger loading in the brainstem, cached phrase patterns).
- **Studio opens big collections fast**: on a 3,000-concept workspace the dashboard state went from 95 s to 12 s on first load and about 4 s after that (pruned and cached confusable-pair ranking, memoized Rosetta archetype matching, shared ledger loading for root-cause hotspots). Results are unchanged.
- **Speed budget in CI**: every CI run now builds a 3,000-concept workspace (about 6,000 links, 30,000 reviews) and fails if `next`, `review` or `readiness` takes longer than 6 s, on Linux, macOS and Windows.
- **Accessibility**: all colour tokens in the dashboard, viewer, exam template and MCP Studio now meet WCAG AA contrast in light and dark themes; added a skip link, landmarks, a consistent heading order, visible focus rings and arrow-key navigation for tabs. axe-core reports zero violations.
- **Tests split by area**: the single large regression file is now 11 focused `tests/test_*.py` modules sharing `tests/_helpers.py`; `syntopik doctor` checks the new layout.
- **Clearer code-runner limits**: compile timeouts are per language (C/C++ 15 s, Rust 45 s) and a timeout now says so plainly instead of reporting a vague failure.
- **CI on current GitHub Actions**: `actions/checkout@v5`, `actions/setup-node@v5` and `actions/setup-python@v6` (Node 24 runtime), clearing the Node 20 deprecation warning on every job.

### Fixed
- The study dashboard no longer scrolls sideways on phones. On a 390px-wide screen, the top-bar buttons, the activity heatmap and the exam-readiness cards used to push the page up to 201px past the edge; they now wrap or scroll inside their own box. Checked on every dashboard tab.
- `syntopik report` no longer says a card is "due now" when `syntopik review` shows nothing due. A card you reviewed in the last 24 hours rests until tomorrow in both, and the report counts it under "more in 7 days".
- Exam triage blocks are never longer than 90 minutes and are labelled with their real length (the protect block could say "90m" while lasting 264m). Every kept salvage target is now scheduled in a block, and when nothing is solid yet the protect time becomes a closed-book re-test of the salvage targets instead of a placeholder.
- `syntopik review --tui` now records how long each card took (capped at 10 minutes), so `syntopik report` can show study time instead of "n/a". A confidence typed after the rating is always read as a percentage, so `3 1` means 1%, not 100%.
- `syntopik next` no longer recommends reviewing a card you already reviewed in the last 24 hours. It now hides those the same way `syntopik review` does, so the two never disagree.
- Blind interleave drills no longer mangle code and multi-line setups: line breaks and indentation are kept (in the dashboard too), and code such as `def f(...)` or `scores = ...` is no longer capitalised to `Def`/`Scores`.
- `syntopik doctor`, the command the start screen suggests when something is wrong, no longer reports "ISSUES DETECTED" with about 24 failures on a normal install just because the optional maths, PDF, chemistry and video extras are absent. When none of them are installed it checks the core and says so. The new `--full` flag lists every extra. Piping CLI output into `head` no longer prints a BrokenPipeError traceback.
- CLI bad input: invalid values now get a one-line error instead of a Python traceback. That covers `profile calibrate --entry-ramp/--challenge-appetite`, unparsable `--frame-json`, and any other ValueError/FileNotFoundError/PermissionError reaching the top level (set `SYNTOPIK_DEBUG=1` for the traceback). `readiness --exam-date`, `report --days`, `review --daily-cap/--days` and `pace --minutes` are range-checked rather than silently ignored or clamped. The profile line shows "Confidence:not yet measured" instead of the confusing "Cal:uncalibrated" right after calibrating.
- The daily plan and the dashboard's "exam is close, try triage" flag now see exams listed in `study-config.json` `exams[]` (what `pace` uses), not only a single top-level `examDate`.
- Dashboard and graph viewer accessibility: every tab of the Studio dashboard, the graph viewer and the Pocket deck now pass axe-core with 0 violations in light and dark (named progress bars, readable Rosetta/planned/sage pills and Pocket status pills, keyboard-focusable inspector panels).
- Pocket phone deck accessibility: readable muted text and rating-button colors in both themes (WCAG AA), a labelled confidence slider, a real page heading, and proper page regions. axe reports 0 violations before and after reveal, in light and dark.
- `syntopik drop` with a missing file no longer creates an empty chapter named after it. It reports what was skipped, keeps the readable sources, and exits 1 when nothing could be read.
- `syntopik import` with a missing file or unknown target prints one clear line instead of a Python traceback.
- After `syntopik drop`, the empty-vault hint now says the material is added but not studied yet, instead of asking you to add notes again.
- `syntopik sunset <slug>` with an unknown chapter now says so and lists the known chapters, instead of previewing an empty archive.
- `syntopik mode` with no argument now shows the current mode instead of silently switching Mentor mode on.
- `syntopik debrief` outside a git project now prints a short explanation instead of git's full usage text.
- **`code_verify complexity` no longer calls a linear solution O(N log N) on noisy timings**: when the measurements cannot decisively separate the two classes, the simpler O(N) is kept with low confidence.
